# VitaminTrack

Учебный React-проект для учёта витаминов и добавок: личный список, ежедневный план и история приёма.

## Возможности

- Регистрация, вход и личный кабинет.
- Добавление, просмотр, изменение и удаление добавок.
- Отметка и отмена приёма на сегодня, история и недельная статистика.
- Поиск и фильтр личного списка по категории.
- Поиск добавок в каталоге [NIH DSLD](https://dsld.od.nih.gov/) и добавление в свой план.
- Деморежим с профилем «Макс».

Дозировку и время приёма пользователь указывает самостоятельно.

## Запуск

Требуются Node.js 22.12+ и npm. Выполните из папки проекта:

```bash
npm ci
npm run dev
```

Приложение: [http://127.0.0.1:5173](http://127.0.0.1:5173). Frontend и backend запускаются вместе; API использует порт 3001.

В Windows можно открыть `start-vitamintrack.cmd` двойным щелчком. Скрипт использует Node.js из `C:\Program Files\nodejs`, устанавливает зависимости при необходимости и открывает страницу после запуска серверов. Оставьте окно запуска открытым, пока пользуетесь приложением.

## Структура

```text
src/       React-приложение: страницы, компоненты, контексты и стили
public/    Статические ресурсы
server/    Express API, авторизация, хранение данных и тесты
scripts/   Скрипт запуска и его тесты
```

Стек: React, Vite, React Router, Lucide и Express. Данные сохраняются локально в `server/data/db.json`; файл создаётся автоматически при первом запуске. Пароли хешируются, сессия хранится в HttpOnly cookie. Каждый пользователь работает со своим списком и историей.

В репозиторий входят исходники, тесты, настройки, README и файлы запуска. Зависимости `node_modules`, сборка `dist`, локальная база `server/data`, временные файлы и переменные окружения исключены через `.gitignore`.

## Соответствие учебному ТЗ

| Требование базового уровня                                          | Реализация                                                                                                                                            |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Регистрация, вход, личный кабинет                                   | `AuthPage`, `AuthContext`, `ProfilePage`, серверные сессии                                                                                            |
| Одна сущность с сохраняемым CRUD                                    | Добавки: создание, просмотр, изменение и удаление; JSON-хранилище backend                                                                             |
| Одна роль и Protected Route                                         | Пользователь видит свой план; `ProtectedRoute` и проверка владельца на сервере                                                                        |
| Отдельная страница внешнего API, поиск, состояния загрузки и ошибок | Каталог NIH DSLD: сведения о добавках, поиск, пустой результат, повтор запроса и импорт в план                                                        |
| Компоненты, props, события, списки                                  | UI, layout, формы и карточки; строки, числа, boolean, объекты, массивы, функции и `children`; `map` и стабильные `key`                                |
| Формы, хуки, состояние и маршрутизация                              | Контролируемые поля, неконтролируемый поиск через `FormData`, `useState`, `useContext`, `useEffect` с очисткой и отменой запросов; React Router и 404 |

VitaminTrack — собственная тема вне списка 40 вариантов; её нужно согласовать с преподавателем. Карточка показывает изображение, а личный план — дозировку и время вместо цены. Эту тематическую замену пункта о карточке товара также нужно согласовать. Отличия функциональных и классовых компонентов объясняются на защите; добавлять класс-компонент ТЗ не требует.

Вторая сущность «приём» и импорт из API уже есть. Две роли с разными правами относятся к повышенному уровню, Redux Toolkit — к необязательному бонусу; они не реализованы.

## Сценарий защиты

1. Зарегистрировать аккаунт, создать и изменить добавку, перезагрузить страницу, отметить приём и показать историю. Удалить добавку, выйти и показать перенаправление закрытой страницы на вход.
2. Открыть каталог, выполнить поиск и показать карточки, импорт и обработку пустого результата. В DevTools → Network открыть запрос `/api/catalog?q=...` и его JSON-ответ: `products`, `total`, `externalUrl`.
3. Показать внешний источник: приложение выполняет запрос NIH на backend в `server/catalog.js`, поэтому браузерный Network показывает запрос к своему API. Для демонстрации именно серверного запроса запустить `server/index.js` в отладчике Node.js, поставить точки останова на вызове `fetchImpl` и после чтения JSON и проверить `url.href`, `response.status` и `data`. Использовать новый запрос: ответы кэшируются на 10 минут. Ссылку из `externalUrl` можно отдельно открыть в новой вкладке и посмотреть исходный ответ NIH; это проверка источника, а не перехват серверного запроса.
